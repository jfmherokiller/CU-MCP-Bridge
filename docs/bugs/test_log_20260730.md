## 测试项目

### 1. `move_to` - AI移动到玩家位置

**命令：** `move_to(x=2.38, y=500.62)` → `move_to(x=2.52, y=500.62)`

**日志：**
```
MoveTo: (2.4,500.6) from (2.4,500.6) pathfind=True
Pathfind: try fall=50 start=(514,1010) end=(514,1010)
MoveTo: path found with 1 waypoints crouch=False
MoveTo: completed
```

**结果：** 看似 completed，但人类早已不在该位置。

**原因：** 第一次 `get_game_state()` 没加 `player="human"`，获取的是 AI 自己的位置。将 AI 发送到 AI 自己的位置→无操作。第二次获取了人类位置但此时人类已经走开了。

**结果：** AI 从 (2.7, 500.6) 向左走到 (-17.4, 504.6)，卡在平台边缘。人类在下方 (-18.6, 484.6)，垂直差 20 格。路径查找失败（`no path found`），回退到直接移动，AI 走到边缘后 stuck，超时后 completed。

**Bug: Pathfinder 无法处理垂直落差** —— AI 找不到下平台的路径。路径查找在 start=(514,1010) 到 end=(493,993) 的格子坐标范围内失败。

### 3. `follow` - 持续跟随

**命令：** `follow(distance=2, max_ydiff=3)`

**日志：**
```
Executing order: follow id=ord_1456038260768
```

**结果：** AI 无变化，仍然卡在 (-17.3, 504.6)。`follow` 内部大概率使用相同路径查找逻辑，同样无法解决垂直落差问题。

### 4. 获取状态时参数遗漏

**问题描述：** `get_game_state()` 默认不加参数时返回的是"当前活跃角色"而非人类。

**验证：**
- 无参调用 → 返回 AI 位置 (2.66, 500.62)
- `player="human"` → 返回人类位置 (-18.58, 484.62)
- `player="ai"` → 返回 AI 位置 (-17.27, 504.62)

### 5. order_id 重复

**日志显示：** 两次不同的 `move_to` 调用使用了相同的 order_id `ord_1456037669952`。OrderManager 生成 ID 时精度不够。

## 修复记录

### 2026-07-30 第二次测试前修复

#### 修复1: 路径查找找不到路径时不再fallback到直接移动

**文件：** `OrderExecutor.cs:MoveToRoutine`
- 当 `Pathfinder.FindPath()` 返回 null 或空路径时，不再创建 `{ targetPos }` 作为回退路径
- 改为日志输出原因并 `Fail()` 终止 order
- **效果：** AI 不再会走到平台边缘卡住，而是直接报错"Pathfinder could not find path"

#### 修复2: 路径检测跳跃不再会跳下悬崖

**文件：** `OrderExecutor.cs:MoveToRoutine` gap crossing 逻辑
- 原来的逻辑：检测前方3格为空则跳跃（会把悬崖边缘误判为需要跳跃的缺口）
- 新增检查：
  1. 检测下降深度：如果 dropDepth < 8 格 → 浅台阶，不跳，直接走过去
  2. 检测前方是否有地面：遥望 ahead=3..15 格是否有固体方块 → 有地面才跳（是缺口），没地面不跳（是悬崖）
- **效果：** AI 只在真正有缺口（对岸有地面）时跳跃，不会跳下悬崖

#### 新增: 游戏内AI调试GUI（AIUI）

**文件：** `AiuiGUI.cs`（新文件）
- 按 **F6** 切换显示/隐藏
- 可拖拽窗口，包含：
  - **Status**：人类和AI的坐标、血量实时显示
  - **AI Management**：Create AI / Destroy AI 按钮
  - **Movement**：X/Y 输入框 + Move 按钮；Start Follow / Stop 按钮（可调距离和Y差）
  - **Actions**：Jump / Sleep / Wait 1s / Wait 5s 按钮
  - **Raw Command**：直接粘贴JSON字符串发送
  - **Log**：操作日志显示区
- 所有操作通过 `OrderExecutor.ExecuteOrder()` 直接执行，不经过 pipe / 文件队列
